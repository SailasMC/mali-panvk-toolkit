# 01 号结论摘要 —— ★ 突破：imapper5 后端**不建 AOSP 也能编出来**

## 一、前提纠正
- AOSP **从来没有** `android.hardware.graphics.mapper` 的 **AIDL** 接口（main/12/13/14 都只有 HIDL 2.0–4.0）
- **V5 mapper 是 native stable-C 的 `AIMapper`**（不是 AIDL）；HIDL 已弃用，AIDL 不支持 pass-through 与指针
- ⇒ **AIDL 路线无对象**（不必再找 mapper .aidl）

## 二、★ 真正的突破（已实测）
Mesa 的 `u_gralloc_imapper5_api.cpp` **已经在不构建 AOSP 的前提下编译 + 链接成功**：
- 复用服务器既有的 **VNDK 树**
- 产出：`imapper5-test/libtest_imapper5.so`（49,016 B），**导出 `u_gralloc_imapper_api_create`** ✓
- 复现脚本：`test-imapper5-vndk.sh`（RC=0）

### 硬阻塞点（已定位并绕过）
**libc++ 双 ABI**：设备/VNDK 的 libui.so 是 `std::__1`，NDK 编出 `std::__ndk1` ✗
→ `-D_LIBCPP_ABI_NAMESPACE=__1` **无效** ✗
→ 正解：`-nostdinc++ -I$V/include/external/libcxx/include`（用平台 libc++ 头）
  `+ -D_LIBCPP_SUPPORT_XLOCALE_POSIX_L_FALLBACK_H` ✓

### 另三个坑
- `log/log.h` → 用 `liblog/include_vndk`
- `ui/{FloatRect,Point,Size}.h` → 用 `ui/include_vndk`
- 还需 `libs/math/include`
- Mesa 源码用了比 A14 更新的 `ChromaSiting::COSITED_VERTICAL/BOTH`（V4 无）⇒ 前置一份生成枚举头即可（**已用此法编过** ✓）

## 三、设备实测（只读 readelf）
- `/system/lib64`：`libui.so`、`libbase`、`libutils`、`libcutils`、`libhidlbase`、`libgralloctypes`、`libvndksupport` + HIDL mapper 全代 ✓
- `/vendor/lib64/hw`：**`mapper.mediatek.so`（stable-C 5.0）** ✓ 与 `mapper@4.0-impl-mediatek.so` ✓
- VINTF：mapper = **native stable-C 5.0（instance `mediatek`）** + HIDL 4.0 兜底；allocator = AIDL V2
- **`libui.so` 导出了 Mesa 需要的全部符号**（签名逐条吻合 ✓✓）
- ⚠️ NDK 的 `libbinder_ndk.so` 是**只有公共子集的 stub**（148 符号、0 个 `AServiceManager_*`）⇒ **NDK 无服务发现层**；设备真机那 17 个都有 ✓
