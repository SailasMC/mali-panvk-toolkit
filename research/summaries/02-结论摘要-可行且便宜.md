# 02 号结论摘要（HIDL / imapper4 路线）—— ★ 可行，且比预期便宜

## 核心结论：**0.5–1.5 人天**，最大阻塞已证明低风险

### 1. prebuilts/vndk **确实预生成了 HIDL 头**
- v29–v34 有；**v35/v36 不存在**（VNDK 快照止于 v34）
- 设备 `ro.vndk.version = 34` ⇒ **正好吻合** ✓
- 目标头路径（每版 7 个文件）：
  `prebuilts/vndk/v34/arm64/include/generated-headers/hardware/interfaces/graphics/mapper/4.0/`
  `android.hardware.graphics.mapper@4.0_genc++_headers/gen/android/hardware/graphics/mapper/4.0/`
- 同快照还白送：**AIDL graphics/common V3 头** + **`gralloctypes/Gralloc4.h`** + 369 个 `.so`

### 2. `hidl-gen` **不用自己构建**
- AOSP 有**预编译二进制**：`prebuilts/build-tools/linux-x86/bin/hidl-gen`（+ 同目录 `lib64/libc++.so`）
- **2 个 curl 即可跑，实测已跑通并生成头** ✓
- Debian trixie 也有包 `hidl-gen`
- 与官方 v34 头逐字节 diff：**6/7 文件完全相同**，仅 `BpHwMapper.h` 多一行 `#include <mutex>`

### 3. 真正的坑（已解决）
VNDK/设备库全用 `std::__1`，NDK 用 `std::__ndk1` ⇒ 符号不匹配 ✗
**修法（只给这一个 TU 加）**：
```
-nostdinc++ -I <vndk>/arm64/include/external/libcxx/include -D_LIBCPP_SUPPORT_XLOCALE_POSIX_L_FALLBACK_H
```
（后一项必需，否则 Android 13 版 libc++ 的 xlocale 兜底与 NDK r27c bionic 的 `ctype.h` 重定义）
**v33 / v34 / hidl-gen 新生成头三套全部 `COMPILE_RC=0` + `LINK_OK`，关键符号逐字符 EXACT MATCH** ✓✓
`libhwbinder` **不需要**（已并入 `libhidlbase`，readelf 实测）

### 4. 运行期几乎零风险
62 个 UND 里只有 9 个来自 libc++，且**全是无命名空间的 ABI 符号**（`operator new/delete`、`__cxa_*`、type_info vtable）
⇒ **没有任何 `std::__1::` 运行期符号** ⇒ 进程里已加载的 NDK libc++_shared 就能满足 ✓

### 5. 设备门槛证据**很强**
- `/vendor/etc/vintf/manifest.xml` 明确声明 **`@4.0::IMapper/default`**，`transport=passthrough` ✓
- 厂商 impl `/vendor/lib64/hw/...@4.0-impl-mediatek.so` 存在 ✓
- **`lshal` 显示该 HAL 约 300 个客户端 PID，前 40 个里 19 个是普通 app uid**
  （`bin.mt.plus` 10569、搜狗输入法 10147 …）⇒ **普通 App 确实在用它** ✓✓
- API 36 已摊平 VNDK 命名空间，这些库在 `/system/lib64` **可直接解析** ✓
- 唯一未证明项：**app 进程内真跑一次 `IMapper::getService()`**（按约束未 push 二进制；建议 30 秒冒烟测）

### 6. 手写最小 IMapper 代理：**不划算** ✗
`getService` 走 `libhidlbase` + `hwservicemanager`；`get` 事务码 = 11；
passthrough 下 `void* buffer` 真正是**进程内虚调用** ⇒ 手写要重实现 hwbinder ioctl + passthrough dlopen + vtable 布局
（≈600–1500 行），还绕不开 `std::__1`。`libbinder_ndk` 用不了（HIDL 在 `/dev/hwbinder`）✗

### 7. ⚠️ **meson 陷阱（必须注意）**
`platform-sdk-version >= 35` 时 meson 走 **imapper5**(`dep_android_ui`) 分支 ✗
而设备是 **SDK 36** ⇒ **必须显式 `-Dplatform-sdk-version=34`** 或打补丁 ✓
且 `ANDROID_API_LEVEL` 同时控制 `ChromaSiting::COSITED_VERTICAL/BOTH`（>=35）的编译分支 ✓

### 8. 工作量与阻塞点排序
**0.5–1.5 人天**（下头+库 10 min；接入 meson 枚举 include 根 2–4 h；2 个编译开关 30 min；冒烟测 30 min）
阻塞点：**app 命名空间 dlopen 直测** > meson 分支/API level > 双 libc++（**已证低风险**）

### 9. 可复用产物

- 产物：`out-imapper4-v33/`、`out-imapper4-v34/`、`gen/`、`gensrc/`、`hidl-gen-prebuilt`
