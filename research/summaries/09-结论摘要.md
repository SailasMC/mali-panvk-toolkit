# 09 号结论摘要（真实世界先例与已知解法）

> 对应正文：[`09-precedents.md`](../09-precedents.md)（577 行，含全部 URL）。
> 本摘要只压缩结论，**证据与出处一律以正文为准**。
> ⚠️ 一句话：**上游没有"Android 上不依赖 gralloc 的 Vulkan WSI"。**

## 〇、★ 一句话结论

所有先例分两类 ——
**(A) 让 gralloc 查询成功**（imapper4/5：需要 `libui`，**plain NDK 不可得**）；
**(B) 根本不查询**：**自分配自己知道布局的缓冲**（公开格式 AHB 或 dma_buf），必要时用 **blit**
把本地图像拷进可共享图像。
⇒ 在本机（无 root、纯 NDK、`ro.vndk.version=34`）条件下，**(B) 是唯一有真实先例支撑的路**。

## 一、三条与 04/05 号互证的新增源码级结论

1. **`-EINVAL` vs `-EAGAIN` 的语义错位（直接死因）**：
   `u_gralloc_fallback.c` 里 `if (!gr_mod || !gr_mod->lock_ycbcr) return -EINVAL;`
   **应当是 `-EAGAIN`** —— 调用方的注释与 `-EAGAIN` 语义都表示"这其实是 RGB，请继续走 fourcc 分支"。
   这正是本机 `IMPLEMENTATION_DEFINED` 失败的**直接**原因。
2. **`-Dandroid-stub=true` 本身不是错误**：stub **不安装**，运行时解析到真库。
   **但**部署目录里若混进 `libhardware.so` / `libnativewindow.so`，`AHardwareBuffer_*` 会全变空实现
   （`getNativeHandle` 返回 NULL）⇒ 必须做"部署目录是否混进 stub"的检查。
3. **`-Dandroid-strict` 与本题无关**（避免误入）。

## 二、★ 真实世界先例（正文 §6，本节最重要）

| 先例 | 关键事实 |
|---|---|
| **leegao《WSI Woes on Mali》**（一手调查，配套 `bionic-vulkan-wrapper`） | 原文：**"on all Mali devices … every device fallback to the slower blit mode using a local primary and shared external secondary buffer"**；"importing BGRA AHBs is disallowed on the Mali driver"；分配优先级 = **`VK_EXT_external_memory_dma_buf`/`VK_KHR_external_memory_fd`（Mali 自 r32p1 通用）→ ion-heap（GKI 4.x 无 dmabuf-heap）→ AHB（最稳）**；**erratum**：`VkMemoryDedicatedAllocateInfo` 与外部内存分配**互斥**（某些 Mali 版本上 dma_buf 路径会失败）。⇒ 缓冲是**他们自己分配**的，布局已知，**不需要问 gralloc** |
| **mapmapbear / ValentinLiu**（MR [!43659](https://gitlab.freedesktop.org/mesa/mesa/-/merge_requests/43659) / [!44464](https://gitlab.freedesktop.org/mesa/mesa/-/merge_requests/44464)） | nubia NX809J / Adreno 840 / Android 16：原文 "**The device log also confirms that Mesa selected the fallback gralloc**"；fallback 返回 `DRM_FORMAT_MOD_INVALID` ⇒ Turnip 误判 TILE6_3/UBWC ⇒ 画面损坏；修法 = **推断 LINEAR**；部署方式 = **Android Updatable Driver APK** + 设置 `DT_SONAME`，**无 root**。⇒ **"应用态自编驱动 + fallback gralloc + 无 root"是实证可行的配置** |
| **PanVK-Mali-Android-Stubs**（`martuniykmisha012-rgb`） | 证据薄弱（正文 §6.3 标注需谨慎） |
| **AOSP 侧**（`android16-release`） | Android 16 **不存在 "mapper AIDL"**：`graphics/mapper/` 只有 HIDL `2.0/2.1/3.0/4.0` + **`stable-c`**（mapper5 是稳定 C API）；取用 mapper5 的**唯一官方姿势**（`libs/ui/Gralloc5.cpp`）是 `IAllocator/getIMapperLibrarySuffix()` → `AServiceManager_openDeclaredPassthroughHal("mapper", suffix, …)` → `dlsym("AIMapper_loadIMapper")`；而该函数在 **`__ANDROID_VENDOR__` 下被编译成 `return nullptr`**（`IServiceManager.cpp:553`），另需 VINTF 声明 + `find` 权限 + sphal 命名空间 ⇒ **应用态自编驱动拿不到** |

**直连 mapper（stable-C / AIDL）是否有人成功过**：**公开渠道查无先例**；上游 issue [!11091](https://gitlab.freedesktop.org/mesa/mesa/-/work_items/11091) 明确**劝阻**直接使用稳定 C 库；树内唯一做到一半的是本项目自己的 `panvk_v19_*`。

## 三、已验证可行的做法清单（按可靠性 / 改动量排序）

| 方案 | 内容 | 可靠性 / 代价 |
|---|---|---|
| ✅ **① 自分配 + blit**（最高） | 渲染到**本地**图像；另建一个**自己 `AHardwareBuffer_allocate()` 的公开格式**（`R8G8B8A8_UNORM=1` / `R8G8B8X8=2` / `B8G8R8A8=5`）外部图像；每帧 `vkCmdCopyImage` 一次。公开 AHB 格式值恰好等于 `HAL_PIXEL_FORMAT_RGBA_8888/RGBX_8888/BGRA_8888` ⇒ **即使 FALLBACK 后端也能命中 RGB 分支而成功返回**；且因是自分配，**可确定是 LINEAR** | 已被 Mali 生态验证；代价 = 每帧一次全屏拷贝 |
| ✅ **② dma_buf 优先**（有真实先例） | 自己申请 dma_buf（或 AHB 取 `data[0]`），用 `VK_EXT_external_memory_dma_buf` 导入，**完全不需要 gralloc 元数据**；**避免** `VkMemoryDedicatedAllocateInfo` 与外部内存同时用 | 中等改动 |
| ✅ **③ 补丁 `u_gralloc` fallback**（改动最小，**需两处叠加**） | **③a 一行**：`-EINVAL` → **`-EAGAIN`**；**③b 必须叠加**：移植 **!43659 的 LINEAR 推断**（`modifier==INVALID` + `offset==0` + `fstat(fd).st_size == row_pitch*height` ⇒ `DRM_FORMAT_MOD_LINEAR`），因为 panvk 对 `MOD_INVALID` **无 handler**（`pan_mod_get_handler(INVALID)==NULL` ⇒ NULL 解引用）。上游 `!43659` **仍 open** ⇒ "在 fallback 里补布局推断"是上游正在讨论的方向 | 最小改动；风险：`IMPLEMENTATION_DEFINED` 对真实 YUV 会误判为 RGB（交换链必然可被 GPU 渲染 ⇒ 合理） |
| ⚠️ **④ imapper4/5 后端**（上游正解） | 需要 `libui`，**libui 没有 stub、plain NDK 不可链接**（!44278 原话）；只有控制 AOSP 构建时才是正路 | 本机构建条件**不具备** |
| ❌ **⑤ 直连 stable-C mapper / mapper AIDL** | 见上；公开渠道无成功先例 | **不推荐作主路** |
| ❌ **⑥ `VK_EXT_headless_surface`** | Mesa 有实现（`wsi_common_headless.c`），但**只能离屏**、无法呈现到 `ANativeWindow` | **不是落地方案**；推荐用途 = **诊断工具**（分离"gralloc/WSI 问题"与"panvk 布局/编译问题"） |

## 四、MTK 现场前置条件（只读检查）

1. `/vendor/lib64/hw/mapper.<suffix>.so`（stable-c / gralloc5）是否存在；
2. `/vendor/lib64/hw/android.hardware.graphics.mapper@4.0-impl-<suffix>.so`（HIDL passthrough）是否存在；
3. AIDL allocator `android.hardware.graphics.allocator.IAllocator/default` 是否 `isDeclared`。

## 五、未解 / 需现场确认（正文 §9）

- 设备是否存在 `/vendor/lib64/hw/mapper.<suffix>.so`；
- **部署目录是否混入 stub 的 `.so`**（会静默毁掉 AHB 全部 API）；
- 交换链的 `hal_format` 究竟是 **34** 还是 **1 / 2 / 5**。

## 六、与本仓库后续进展的关系（事后回填，便于对照）

本摘要成文于 09 号任务时期。其后两条**由本仓库实测**的进展修正/延伸了本文的判断：

1. **方案③ 已落地为 v50**：`-EINVAL→-EAGAIN`（③a）+ `panvk_infer_linear_modifier()`（③b）
   + `vk_android.c` 的 AHB 自描述回退，三文件**严格加性**；产物 md5 `e08e0764…`
   ——但 **v50 从未上机**（[`../../docs/09-mobilegl-integration.md`](../../docs/09-mobilegl-integration.md) §24、[`../11-wsi-patch-implementation.md`](../11-wsi-patch-implementation.md)）。
2. ★ **"WSI 是卡点"这个前提被真机探针推翻**：`win`/`headless`/`winimpdef` 三路
   `vkCreateSwapchainKHR` **全部 `VK_SUCCESS`**；唯一可复现的 `-1000072003` 只在 AHB
   `IMPLEMENTATION_DEFINED(0x22)` 上；而真正让 GPU 掉线的是**执行 draw**——
   kbase **CSF fatal exception `0xc3`**（`docs/09` §25、[`../12-probe-run-results.md`](../12-probe-run-results.md)）。
   ⇒ 本文方案①②③ 对"**能不能创建交换链**"仍然有效，但**没有任何一条能解决 `-4`**。
