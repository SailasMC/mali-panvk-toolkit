# 06 号结论摘要（PanVK Android WSI 深挖）—— 含"决定性事实"

## 〇、★ 决定性事实（本机 WSI 起不来的根因）
```
/dev/dma_heap/system 权限 0444  → 实测 O_RDWR 失败、O_RDONLY 成功
kbase_kmod.c:1269 用 O_RDWR 打开 → 失败
 ⇒ kbase_kmod_supports_dmabuf() = false
 ⇒ panvk_wsi_init 落到 sw_device = true、supports_modifiers = false
 ⇒ DRI3 / raw-fd 路径【一行都没走到】
```
⇒ 这**足以解释"WSI 起不来"**，与 u_gralloc 的失败是**同一根因链上的两处表现**。

## 一、架构事实
1. `panvk_wsi.c` 只有 **122 行**，**不实现 `vkCreateSwapchainKHR`**；它只算 kbase 开关 → `wsi_device_init()`（:79-88）→ 设 `physical_device->vk.wsi_device`（:109）。真正代码在 `src/vulkan/wsi/`，经生成的 `wsi_common_entrypoints` 弱符号路由。
2. Android 上通用 WSI 的 swapchain-image **被硬编码关闭**（`wsi_common_is_swapchain_image()` 在 ANDROID 恒 false，`wsi_common.h:333-338`）；panvk **完全不实现 `VK_KHR_android_surface`** ✓ ⇒ Android 的 WSI 实体就是 ANB/AHB（`panvk_android.c`）。
3. `VK_KHR_swapchain/surface/present_wait` 全被 `#ifdef PANVK_USE_WSI_PLATFORM` 包住（`panvk_vX_physical_device.c:119-127`），该宏只在 **x11/wayland/display** 编译时定义。
4. `VK_KHR_display` 在 Android 被 meson 明确排除（`src/vulkan/meson.build:57 not with_platform_android`）；`VK_EXT_headless_surface` 有暴露，但纯 android 构建下无 swapchain ⇒ 只能"看不能用"。
5. 75/101/298 三点 = image/buffer req 与 fd memTypeBits **交集为空** / 裸 AHB 拿不到 type；共同根因是 `panvk_android_get_fd_mem_type_bits()` 在 `GetMemoryFdPropertiesKHR(DMA_BUF)` 失败时**静默返回 0**（`panvk_android.c:46-58`）。同链路另有 `vk_android.c:149`（u_gralloc 起不来）/`:218`。
6. modifier **强制**：`vk_gralloc_to_drm_explicit_layout()` 直接照抄 `info.modifier`，**无 LINEAR / 未知回退**（`vk_android.c:174`）⇒ 未知 modifier → `pan_mod_get_handler()` 返回 NULL → `assert(image->mod_handler)` / NULL 解引用 = **SIGSEGV，不是 VkResult**。
7. panvk 只认 **afbc / 16x16 U-interleaved / interleaved_64k / afrc / linear**（`pan_mod.c:807-815`）；**MTK 16L32 只在 Gallium panfrost，panvk 没有**（`pan_format.h:24` 的注释是误导）。
8. WSI 侧默认只承认 `DRM_FORMAT_MOD_LINEAR`（AFBC 被默认关闭的 `PANVK_DEBUG_WSI_AFBC`(1<<13) 挡住，`panvk_physical_device.c:1921-1922`）。
9. panvk **没有 `VK_EXT_external_memory_host`** ⇒ X11 MIT-SHM 快路不可用 ⇒ 退到 `x11_present_to_x11_sw()`（xcb_put_image）。
10. 真机修正：`/dev/dri` **有 card0**（0660 system:system，**无 renderD\***）⇒ panvk 要求 DRM render node（`panvk_instance.c:86-88`）⇒ **DRM 路不可用**；`/dev/mali0` 666，O_RDWR 成功 ✓。

## 二、路线排名（06 的建议）
| 排名 | 路线 | 代价 | 说明 |
|---|---|---|---|
| **R1** | 零改动 **X11 + CPU/SW present** 上屏 | 低 | sw_device 已自动选中，不需 dma-buf/modifier/render node |
| **R2** | headless + `MESA_VK_WSI_HEADLESS_SWAPCHAIN=1` | 零 | **诊断用**（= 我们已打的 v47 ✓）|
| **R3** | 自建 **LINEAR** image + 上层拷贝 | 中 | 最稳 |
| **R4** | ANB/AHB 原生上屏 | 中高 | 性能最好，但**必须先打"未知 modifier 干净拒绝"补丁**防 SIGSEGV，并确认 IMapper4 实际 modifier |
| **R5** | 改 kbase dma_heap 为 O_RDONLY ⇒ 解锁 DRI3 raw-fd | 未知 | 潜在最优，但依赖 2 个未验证假设 |

⭐ **R4 的省事杠杆**：本机是 **ARM gralloc**（`ro.vendor.arm.gralloc.*` 全套 + `libarm_gralloc_properties_sysprop.so`），
它**尊重 `no_afbc_usage` 位**（`0x200000000000000`）⇒ 让上层申请时带该 usage，很可能**直接给 LINEAR** ⇒ panvk 不改也能用。

## 三、未验证项（如实标注）
