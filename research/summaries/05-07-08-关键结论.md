# 05 / 07 / 08 三篇关键结论（决策依据）

## 05 —— 绕开 u_gralloc 的最小补丁【推荐方案 A】
- **只改 1 个文件**：`src/vulkan/runtime/vk_android.c`，新增「AHB 自描述回退」约 **90–105 行**，**无需 meson 改动**
- **严格加性**：仅当 `u_gralloc_get_buffer_basic_info()` 已失败才生效（正常设备零影响），带 `PANVK_GRALLOC_NO_FALLBACK=1` 开关
- ⭐ **前提纠正**：本树交换链走 **AHB**（不是 ANB），且那个 `AHardwareBuffer` 是**我们项目自己的 `panvk_wsi.c` 分配**的（上游没有）⇒ 我们带 `CPU_READ_OFTEN` 分配 ⇒ **"线性"可被证明而非猜测**
- `AHardwareBuffer_describe()` **已是 .so 的 UND 符号**（libnativewindow.so 提供）⇒ 无链接/meson 改动
- **真正要改/要编的树**：`/root/zenithblue/work/mesa`；唯一有产物的构建目录 `/root/zenithblue/build/android-v4`
- **重编范围**：`vk_android.c.o` → 重打 .a → 重链 20MB .so，约 3–5 条 edge，**预计 30–60 秒**
- 两个坑：① 新 u_gralloc 后端必须插在 FALLBACK **之前**（否则死代码）② `-Wl,--no-undefined` ⇒ 用 `lockPlanes` 要在 `src/android_stub/nativewindow_stub.cpp` 补桩
- **回滚陷阱**：`work/mesa` 有 **45 个未提交改动**，`vk_android.c` 在其中 ⇒ **禁止 `git checkout --`**，只能 cp 备份/覆盖
- 改动量 A ≈ 90–105 行 / 1 文件；**成功率 70–80%**；长期仍建议走 mapper v5 拿真实 modifier

## 07 —— MobileGL 侧【结论：不存在"只改配置就出画面"的路】
1. **默认帧缓冲物理上就是交换链图像**（`VkRenderPassManager.cpp:1077-1096` 用 swapchain imageView 当 attachment，finalLayout=PRESENT_SRC；**不存在 默认FBO→交换链 的 blit**）
2. 唯一 present 入口 `eglSwapBuffers → BackendObject.cpp:396 → vkQueuePresentKHR`（`VulkanRenderer.cpp:12979`）；全树无 AHB/ANativeWindow 直写、无 CPU 回读送窗口
3. 全树 **无任何 HEADLESS/NO_WSI/OFFSCREEN/PRESENT 开关**；只有 `MOBILEGL_MAGMA_FRAMESINFLIGHT` 影响图像数
4. ⭐ **一行杀招**：`MESA_VK_WSI_HEADLESS_SWAPCHAIN=1` ⇒ Mesa 把**任意 surface**换成 headless 交换链，其 `queue_present` **空操作返回 VK_SUCCESS** ⇒ 把"WSI 建链失败→崩"降级为"干净跑完→黑屏"，**一行判定"坏的只有 WSI"**
   （可配 `MESA_VK_WSI_PRESENT_MODE=fifo|immediate|mailbox`）
5. ⚠️ `MOBILEGL_BACKEND_TYPE` 默认是 `DirectGLES`，不显式设 `DirectVulkan` Magma 链根本不启动
6. `MOBILEGL_ASSERT` 已被 Release 编掉（`strings|grep -c 'Assertion failed'` = 0）；`VK_VERIFY` 失败只记一行日志后**继续执行** ⇒ 崩点常在"失败后仍用 NULL 句柄"
7. shim `/root/mgl_icd/vkshim_mgl.c` 目前是**纯转发+日志**，但 **WSI 四个入口都已挂钩**（:299 surface / :515 create swapchain / :817 get images / :844 present）⇒ 若将来要真绕开交换链，这里是落点

## 08 —— ZL2 Surface 契约【结论：切桥可绕开交换链，但代价是 CPU 合成】
1. Surface 唯一入口：`ZLBridge.setupBridgeWindow` → JNI `egl_bridge.c:80` → `ANativeWindow_fromSurface` → `pojavWindow`
2. ⭐ **用哪个桥完全由 `POJAV_RENDERER` 字符串决定**（`egl_bridge.c:134-197`）：
   - `opengles*` ⇒ GL 桥（EGL `eglCreateWindowSurface`）
   - `custom_gallium` / `vulkan_zink` / `gallium_freedreno` / `gallium_panfrost` ⇒ **OSMesa 桥：无 EGL、无 VkSurface**（`ANativeWindow_lock` + `OSMesaMakeCurrent`）⇒ **一次都不调 vkCreateSwapchainKHR**
   - `gallium_virgl` ⇒ vtest socket
3. **插件契约没有"离屏/无窗口"开关**；`boatEnv` 在 ZL2 全树 0 命中（只 FCL 要求但从不消费）
4. ⚠️ **红线**：`renderer[0]` 必须是那六个字符串之一，否则 `br_init` 为 NULL ⇒ `egl_bridge.c:194` NULL 调用 ⇒ 启动即崩（FCL 有兜底，ZL2 无）
5. ❌ **不能**保留 `opengles*`(MobileGL DirectVulkan) 又让 panvk 不建交换链：无任何开关（唯一 pbuffer 分支是"窗口已死"）；MGL 的离屏判决在构造时 `VulkanRenderer.cpp:2983 m_presentsToAppWindow=(window!=0)`
6. ⚠️ **切桥≠用上我们的 panvk**：Mali 上 ZL2 只能 `dlopen("libvulkan.so")`（turnip 分支被 Qualcomm 判定挡死），叠加 §11 的 loader 封堵 ⇒ 仍需 §12 的转发垫片
7. ZL2 的 `LD_LIBRARY_PATH` 里 `/system/lib64` 排在插件目录**之前** ⇒ "靠搜索顺序顶替 libvulkan.so" 必须实测
