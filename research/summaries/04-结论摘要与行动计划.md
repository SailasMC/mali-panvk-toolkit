# 04 号研究结论摘要 + 行动计划（Mesa u_gralloc 精读）

## 一、结论：现有 5 个后端在本机【全部不可用】
| 后端 | 为什么不行 |
|---|---|
| CROS | 要求模块名 `"CrOS Gralloc"` ✗ |
| LIBDRM | 要求 `"GBM Memory Allocator"` + `/dev/dri`（本机 EACCES）✗ |
| QCOM | 高通专用（name/author 精确匹配）✗ |
| FALLBACK | create 恒成功，但只给 `DRM_FORMAT_MOD_INVALID` ⇒ panvk 里 `pan_mod_get_handler(INVALID)==NULL` ⇒ `pan_layout.c:69` 的 assert 在 NDEBUG 下被编掉 ⇒ **NULL 解引用崩溃** ✗ |
| imapper4/5 | **根本没参与编译** —— 构建带 `-Dandroid-stub=true` ⇒ `meson.build:1055-1057` 跳过探测 ✗ |

⇒ **必须新增后端**。

## 二、ops 契约要点（写新后端必须遵守）
- 必需：`get_buffer_basic_info` + `destroy`
- `drm_fourcc` 必须非 0；`num_planes` ∈ 1..4；**`offsets[0]` 必须为 0**（`i>0 && offset==0` 会被判 disjoint 直接拒）
- `strides` 单位是**字节**（legacy 用 `pixel_stride × bpp`）
- `modifier = DRM_FORMAT_MOD_INVALID` 表示"未知" ⇒ 对 Vulkan 显式 modifier 图像**非法**（这就是 FALLBACK 崩溃的根因）

## 三、正解：直连 mapper AIDL（不依赖 AIDL 代码生成）
```
dlopen("libbinder_ndk.so")                    ← NDK 自带 ✓
  → AServiceManager_openDeclaredPassthroughHal("mapper", "<vendor>")
  → dlopen("mapper.<vendor>.so") → AIMapper_loadIMapper
  → getStandardMetadata(buf, 7=FOURCC / 8=MODIFIER / 15=PLANE_LAYOUTS / 5 / 10 / 14 / 17)
```
⇒ 这条路的**全部依赖都是运行时 dlopen**，**不需要 hidl-gen、不需要 AIDL 编译器** ✓✓

## 四、⚠️ 最重要的现场发现（已核实）

**已经有一段 275 行的 mapper AIDL 客户端**（标签 `P0A-V19` / `[P0A-V19-FULLPLANE]`，含
`dlopen libbinder_ndk` / `AServiceManager_openPassthrough…` / `AIMapper_loadIMapper`），
但它**寄生在 `fallback_gralloc_get_buffer_info` 末尾(:422)** ✗
—— 而该函数对 **YUV / IMPLEMENTATION_DEFINED** 在 `:112-123` **提前 return** ✗
⇒ **mapper 路径对这两类格式永不执行**（当前只对 RGBA 一族生效）⇒ **必须提为独立后端并前插**。
