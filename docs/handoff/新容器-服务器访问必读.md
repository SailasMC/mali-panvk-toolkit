# 新容器 · 服务器访问必读（重要更正）

> 实测时间：本会话（换容器后）
> 结论：**当前容器里没有任何可用的 ssh 客户端** ✗ ⇒ `连接服务器.sh` 的 ping/cmd/pull/push 在本容器**用不了** ✓

## 1. 实测到的环境事实

```
PATH = /data/data/com.dsharnessmobile.shell/files/usr/bin:/system/bin
✗ 没有 ssh / scp / sftp / dbclient（逐路径检查过）
✗ apt-get install openssh / openssh-client 都失败
   （Termux 源可达，但本机 dpkg 已损坏："6 expected programs not found in PATH"）
⇒ 结论：**不要指望用系统 ssh**，改走 DSH 内置 SSH 工具 ✓✓
```

## 2. 【正确做法】用 DSH 自带的 SSH 工具（不依赖系统 ssh ✓✓）

DSH 的 `ssh_*` 工具是**在 Node 内实现的**，跟系统有没有 ssh 无关 ✓。

**请操作员做一次（1 分钟 ✓）**：
```
设置 → SSH 资源 → 新增
   host       = 64.81.112.146
   port       = 22
   username   = root
   auth       = 私钥
   私钥路径    = /data/data/com.dsharnessmobile.shell/files/home/.ssh/id_ed25519
                （即旧容器里一直用的那把 ✓ 同一台设备上的同一个 App home ✓）
   ★ 打开开关：「允许 AI 自动连接已保存服务器」✓
```
配好后，AI 侧就能：
```
ssh_list                      → 看到这条已保存资源
ssh_connect_profile("资源名")  → 连上（并把它设为当前连接）
ssh_exec("命令")              → 执行命令
sftp_read / sftp_write / sftp_upload_dir / sftp_download_dir  → 传文件
```
⇒ 与本项目需要的能力**完全等价** ✓（编译、读报告、取 APK、推补丁都能做 ✓）

## 4. 如果 `ssh_connect_profile` 报"开关未开"

工具会明确提示；此时**不要**让 AI 用会话里出现过的密钥去 `ssh_connect`（那会把私钥写进请求/日志 ✗）
⇒ 请操作员在设置里打开那个开关，或者直接在 SSH 面板里手连 ✓

## 5. 备用方案（前两条都不可行时）

```
① 在【有 ssh 的旧容器/环境】里跑 `bash 连接服务器.sh pull <远端> <本地>`，
   再把文件同步到本工作区 ✓
② 直接用 sftp_* 工具（同样不依赖系统 ssh ✓）拉文件到本地 ✓
③ 若确实需要系统 ssh ⇒ 需要先修复容器的 dpkg（超出本项目范围 ✗）
```
