# 在免 root 的 Android 上让 Mali GPU 用上开源驱动
## —— `mali-panvk-toolkit` 项目总览与当前状况

---

## 一、这个项目在做什么

让**没有 root 的 Android 手机**，把厂商闭源的 GPU 驱动换成**开源的 Mesa PanVK**（kbase 后端，
面向 ARM Mali 第 12 代 CSF 架构），并把它一路接进 **Minecraft Java 版启动器**
（Zalith Launcher 2 / FCL + MobileGL DirectVulkan），最终目标是**稳定跑起商业游戏**。

一句话概括：**在移动端最封闭的一层（GPU 驱动）上，做一次从内核接口到游戏画面的全栈打通。**

## 二、为什么这件事难

| 难点 | 说明 |
|---|---|
| **驱动不开源** | 手机 GPU 驱动长期是厂商黑盒；Mali 的开源驱动（Panfrost/PanVK）在移动端的实战记录极少 |
| **没有 root** | 无法替换系统驱动，只能走"按应用加载自定义 ICD + 转发垫片"的路子 |
| **新架构** | 第 12 代 Mali 走 **CSF + kbase**（命令流由固件调度），与旧 Job Manager 架构差异巨大 |
| **寄存器级排错** | 出问题时往往只有一个 `VK_ERROR_DEVICE_LOST`，没有栈、没有文件名、没有行号 |
| **上游路径未必覆盖** | 厂商内核接口（kbase）与上游期望存在系统性差异，需要逐条比对与桥接 |

## 三、技术路线

```
Zalith Launcher 2 / FCL（Minecraft Java 启动器）
        │  要求 OpenGL / Vulkan
        ▼
MobileGL（DirectVulkan 后端）
        │  标准 Vulkan 调用
        ▼
Vulkan 转发垫片（本项目自建，把调用导向自定义 ICD）
        │
        ▼
Mesa PanVK 驱动（本项目编译，kbase / CSF 后端，Mali v12）
        │  kbase ioctl
        ▼
厂商内核驱动（不修改、不 root）
```

配套自建：**驱动插件 APK 打包链**（`aapt2` + `zipalign` + `apksigner`）、
**设备侧探针**（可直接用 `--icd=` 加载任意驱动版本做 A/B）、**真机取证脚本**。

## 六、当前状况（截至本快照）

> **结论：尚未跑通。** 一次**真实的绘制**（走 tiler 的三角形）就会让 GPU 翻译失败并
> `VK_ERROR_DEVICE_LOST`；长跑场景还会出现"命令流停在 fence 之前"的卡死族。

### 6.1 绘制失败：已收窄成一句可执行的话

> **软件侧"绑定成功（`ret=0`）"的某个 72 KiB（`0x12000`）GPU VA 区间，
> 内核没有为它的最后一页建立页表项 —— GPU 一访问就 `TRANSLATION_FAULT`（exception `0xc2`/`0xc3`）。**

三轮单变量实测（改动均确认生效）：

| 版本 | 对同一对象的改动 | 故障地址 | 结论 |
|---|---|---|---|
| v126 | 基线 | `…d9e000`（区间末 −0x1000） | 区间 `…d8d000..d9f000` |
| v128 | 该 BO 加一页 | `…d9d000` | **故障跟着区间平移** |
| v129 | 该 BO 改为 2 的幂 | `…d8f000` | **仍落在"另一个 0x12000"的末页** |

⇒ 不变量成立：**故障永远落在"某个 0x12000 区间的最后一页"**，
且它**不是** tiler 描述符/几何缓冲（改其尺寸三次，真凶始终是另一个 72 KiB 对象）。

### 6.2 卡死族：机制已定位，修复未完成

逐秒采样显示：三个跨子队列的 `syncobj` 会**同时冻结**（如 `s0=6104 / s1=12119 / s2=6285`），
即 CSF 命令流停在"等待"之前；随后应用侧 fence 永不满足 ⇒ 看门狗 `-4`。
该现象具有强随机性（成功时可达 32 万作业 / 约 9 分钟，失败时数百作业即停）。

### 6.3 另发现一个独立缺陷

若干 GPU VA 绑定区间**互相重叠**（一个 72 KiB 区间与两块 256 KiB 的池 slab），
内核对这些绑定**均返回成功**。已列为"画面出现面板/重复内容"的**头号候选**。

### 6.4 已逐条实测排除的方向

行距/pitch · AFBC · 覆盖层 · 中间表示三轮 · M1/M2 · 呈现同步 · tiler `chunk_size` ·
堆上下文地址 · 描述符环容量 · kbase 别名区 · 填充式陷阱 · 堆耗尽 · 诊断构建产物 ·
"空洞曾住过对象" · 几何缓冲内容 · "绑定比对象多一页" · "池取整" · "2 的幂" ·
"是 tiler 那个对象" —— **共 19 条**，每条都有实测判据，详见 `docs/10`。

## 七、工程方法（这个项目的另一半价值）

1. **单变量**：一次只改一处，改动必须确认生效（否则否定无效）。
2. **叠加实验前先回滚上一个**（本项目曾因此污染过一次实验，已记入教训）。
3. **结论前先复算差值**（曾因把 `1 MiB` 当成"堆的全部变化量"而误判一次结构耦合）。
4. **每个结论都要有判据**：判据行 / 日志原文 / 地址算术，缺一不算结论。
5. **把"没修好"如实写进文档** —— 包括 9 次自我方向修正与一次实验污染。
